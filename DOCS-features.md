# FEATURES: game-research

> Feature map + core-flow ground truth (skill: `e2e-ground-truth`). A
> user-visible change updates its row in the same commit.

- **Primary target:** desktop (Flutter web in a Chrome `--app` window on
  HDMI-0, wrapper on `127.0.0.1:8805`)
- **Driver:** flutter-web-drive (headless chromium) + private `Xvfb :147`
  (xdotool hotkeys, dmenu, flash, x11grab) + fake Steam / models / todo
- **Run one flow:** `e2e/run.sh build`, `e2e/run.sh up`, then `e2e/run.sh F1`,
  `e2e/run.sh F1-check`, `e2e/run.sh F2`, `e2e/run.sh F5` (after F1 + F1-check), `E2E_LAYOUT=dual e2e/run.sh up` + `e2e/run.sh F4`, `e2e/run.sh down`
- **Artefacts:** `~/data/claude-scratch/e2e/game-research/<run>/`

## Feature map

| feature | how to reach it | expected outcome |
|---|---|---|
| Game picker | window opens -> capsule grid (`/api/games`) | one tile per Steam game with a manifest (tools skipped); art: Steam's librarycache (flat, `<id>/` or hashed `<id>/<hash>/library_600x900*` or `library_capsule.jpg`), else downloaded from the Steam CDN (`library_600x900.jpg`, then `header.jpg`) into `<data>/art/<id>.jpg`, a miss remembered 1 day (`GAME_RESEARCH_ART=off` and test mode never go online), else a procedural hue tile; a half-downloaded game shows a download glyph and its progress bar; no games = red empty glyph; no text |
| Autostart | open PlayStudy (launcher adds `?autostart=1`) | a 3 s ring drains around the stop button, then the last game (default Librarian 4197610) starts; Esc or the button cancels |
| Start | pick capsule -> play button (`start`), or autostart | Steam client down: `systemd-run --user --unit playstudy-steam-<port> steam steam://rungameid/<id>`; up: `steam <uri>` handoff (again every 30 s while Steam runs but the game does not); spinner ring while waiting; recording starts when a game-sized window appears (Proton class `steam_app_<id>`); failures show the error glyph and an `error` log line |
| Event log + CLI | `<data>/playstudy.jsonl`; `playstudy --status` etc. | every step logged; control commands in CLAUDE.md |
| Markers by button | thumbs up / thumbs down / question / note buttons | line in `markers.jsonl` (wall, offset_s, tag, note); counter +1; 300 ms border flash in the tag colour on the game output; tick sound; the note line opens for every tag |
| Note by button | any marker button -> one-line field -> Enter (Esc = empty note) | marker stamped at the button press, note text added on Enter; pressing another marker closes an open field empty |
| Hotkeys | Mod+F1 good, Mod+F2 bad, Mod+F3 confusing, Mod+F4 note, Mod+Shift+F4 stop | same as the buttons, each shown as a key legend beside its button (`Super+F1`, from `kHotkeys`); every marker key asks for a note line through dmenu (`ask=1`), stamped at the key press; Esc or an empty line asks again at once (all four tags) until a note arrives, and only a stopped session keeps an empty note (the copy gate then catches it); keys exist only while a session records (sxhkd unit `game-research-keys-<port>`) |
| Auto stop | quit the game | session ends when no process carries `AppId=<id>` any more (after it was seen once); `ended_by: game-exit` |
| Recording | any session | `~/data/game-research/<stamp>-<game>/recording.mkv`: x11grab of the monitor the game window is on (`xrandr --listmonitors` x window rect, else the primary; `record_start` logs `output` + `output_why`), default-sink monitor audio (never a mic), HEVC NVENC cq 14, one chapter per marker; gpu-screen-recorder path: `-q very_high`, audio `-ac opus` |
| Analysis job | starts after Stop (`systemd-run --user`) | `analysis/status.json` drives the ring (`state` running / waiting / interrupted / done / failed, `tokens`, `cost_usd`, `eta_s`, `started_unix`); stages resume from their own outputs; one job at a time machine-wide (`<data>/analysis.lock`: pid + start time), a second one is `waiting` and starts when the first ends |
| Resume | `game-research-resume.timer` (`install.sh --step resume`), 2 min after boot then every 15 min | `game_research_analyze --resume-all` relaunches interrupted jobs, waiting ones whose retry time passed and sessions never analysed, one at a time, never while `<data>/recording.pid` is live; `failed` is never retried; also deletes `recording.mkv` 14 days after the game's `finish.json` |
| Finish | `game_research_analyze --finish <slug>` | one Opus call merges every session draft (v1 sessions with only `draft_en` too, one per file path) into `games/<slug>/DOCS-research-<slug>.md` and `-report.md`, same 250-line rule, then the report's Discord version (`report_discord`); `<data>/games/<slug>/finish.json` + `status.json`; todo task "MANUAL WORK REQUIRED: review <game> research report" |
| Stage 1 | automatic | `scenes.json`, `still.jsonl` (no motion >= 20 s), `frames/` (every marker + scene cuts at most one per 10 s, <= 1280 px), `clips/` (10 s per marker, stream copy, up to +1 s at the start keyframe) with `m_NN_<tag>.jpg` beside each clip (a full-resolution still at the marker, JPEG `-q:v 2`), `contact/sheet_*.png` |
| Stage 2 | automatic | `captions.jsonl`: one line per frame stage 3 will use (60 per hour, marker frames first; none in the first 2 s unless a marker is there), 8 frames per call with one JSON object per frame checked by code (a malformed batch falls back to single frames), `tier`, `model`, `skipped`, `usage` (a call's tokens sit on its first row); chain haiku -> OmniRoute `agnes/agnes-2.5-flash` -> ollama `qwen3-vl:30b-a3b-instruct`; a frame no tier captions fails the stage (a later run resumes) |
| Stage 3 | automatic | one Opus call; `<target>/docs/research/games/<game>/DOCS-research-<game>-<stamp>.md` (one per session, English, never overwritten; the prompt carries the earlier drafts, every question has a `- **Status:** answered|partial|open` line) written uncommitted without the template's `Why we ask:` lines, blank runs collapsed, at most 250 lines (over: one follow-up Opus call asks for <= 240, a second overflow fails the stage); `stage3.json` has `draft`, `tokens`, `cost_usd`; then its Discord version (see that row); todo task "MANUAL WORK REQUIRED: review <game> research draft" (`--new-note`); frames shown: ceil(60 x hours), at least 1, marker frames first |
| Discord version | automatic after every session draft and every merged report; `game_research_analyze --discord-backfill` for older docs | `X.md` gets a sibling `X.discord.md` (never taken for a draft: `priorDrafts` needs `-<stamp>.md`): one more Opus call asks for <= 1900 characters of Discord markdown (`#`..`###` headings, bold, `-` lists, no tables, key findings); code names every break (over 1900, a `\|` row, `####`+, empty), ONE rewrite is asked, then it fails closed. A failure never fails the job or the merge: `stage3.json` `discord` / `finish.json` `report_discord` is `ok` or `failed: <reason>`, the doc stays, no sibling. A re-merged report clears `report_discord` and deletes its old sibling. Saving an edit of a doc through the panel deletes its sibling (an edit of a `.discord.md` itself is kept). Backfill: under the job lock, waits while recording, skips existing siblings, usage limit exit 4, other failures reported per doc (exit 1); status `<data>/discord_backfill.json` |
| Game fps | MangoHud for games only (`install.sh --step fps`: package, invisible HUD (`alpha=0`; `no_display` would stop the logger), `<data>/mangohud.conf`; removes the old session-wide layer). The wrapper writes a `MANGOHUD=1 MANGOHUD_CONFIGFILE=… %command%` launch option for every installed game into `localconfig.vdf` at start and before each launch, only while Steam is down and never from a scratch data dir against the real Steam root; a stale own config path is repointed | CSVs land in `<data>/fps-spool/`; at stop the overlapping ones move to `<session>/fps/` and `session.json` gets `fps: {avg, p1_low, min, samples}` (null without a log); events `fps_launch_option`, `fps`; spool pruned after 7 days |
| Target picker | folder chips under the controls | any `~/src/*` with `docs/research/DOCS-research-questions.md`, default cleanup-plate; kept in `~/data/game-research/settings.json` |
| Past sessions | right column | capsule, start `MM-DD HH:MM`, length, marker counts, progress ring (accent running, green done, red failed, amber hourglass waiting for a usage limit, amber pause interrupted), and numbers with an icon: token total, cost, stage, items done/total, minutes left, average game fps; fields missing in old sessions are simply not shown |
| Draft panel | page button on a row (enabled once the draft exists) | an in-app panel over the window: the draft rendered as markdown, an edit toggle (plain text) and save (`PUT /api/doc`); only `<target>/docs/research/**.md` is readable or writable (403 elsewhere, `..` and symlinks resolved); nothing is spawned; row buttons ignore taps for 5 s after the launcher opened the page or a game / Steam window opened or closed (the stray-click fix for `open-draft` firing alone) |
| Finished control | flag on a game tile (needs a session draft) | `POST /api/games/<id>/finish` runs `game_research_analyze --finish <slug>` (systemd-run like a session job); ring and numbers from `<data>/games/<slug>/status.json`; done: the flag turns into a check and opens the report in the panel |
| Discord notes (API) | `GET /api/games/<appid>/notes` | kuhy's own marker notes of every session of the game (analysed or not), oldest first, cut into message parts: header `**<game>** · my notes n/of`, a `__YYYY-MM-DD__` line per session (repeated when a session continues into the next part), one line `<emoji> \`h:mm:ss\` <note>` per marker (👍 👎 ❓ 📝, no trailing space for an empty note); at most 10 markers and under 2000 chars per part; a note too long for one message is cut with `…`; JSON `{slug, parts:[{n, of, text, markers:[{session, i, tag, time, note, line, still}]}]}`; reading it also queues the missing stills of older sessions (one ffmpeg at a time, never while `recording.pid` is live; `still:false` until cut) |
| Marker still | `GET /api/sessions/<stamp>/still/<i>` | `image/jpeg` of marker `i` (1-based, the clip numbering) or 404 |
| Copy to clipboard | `POST /api/games/<appid>/notes/<n>/copy?what=files\|text`, `POST /api/sessions/<stamp>/markers/<i>/copy` | `helpers/clip_owner.py` (killed and restarted per copy) owns CLIPBOARD on `GAME_RESEARCH_DISPLAY` with `text/uri-list` + `x-special/gnome-copied-files` (the stills) and `text/plain`/`UTF8_STRING`; `files` = the part's stills as captioned copies (+ text), `text` = text only, marker copy = its line + its captioned still; every staged image is the full-resolution still with a dark band added below it that holds the whole note (`helpers/caption_still.py` via `GAME_RESEARCH_CAPTION_CMD`, JPEG q92, staged as `<data>/share/<slug>-<n>/NN_<tag>.jpg` or `<data>/share/marker-<stamp>-<i>/01_<tag>.jpg`, originals in `analysis/clips` untouched); reply `{ok, files, chars}`; 404 missing (a files copy with no stills yet too), 400 bad `what`, 409 while a session records, when a marker has no note (text copies too) or the display cannot be opened, 500 helper or captioner failed. Spike 2026-11-12 (Chromium on Xvfb): a paste with files offered delivers the files and drops the text in the same paste event, so Discord gets files or text per paste, not both |
| Marker note (API) | `POST /api/sessions/<stamp>/markers/<i>/note` body `{"note": "..."}` | rewrites that session's `markers.jsonl` atomically (same line order, only that line's `note` changes; `i` = position in offset order, as in `/notes`); 200 `{ok}`, 400 empty or bad body, 404 no such session or marker, 409 while that session records |
| Copy short | copy icon in the reader bar (`copy short`) | `GET /api/doc` answers `short` (a sibling `X.discord.md` exists); `POST /api/doc/copy?path=<doc>` puts the sibling's text on the clipboard (text only, same helper; 404 without a sibling, 403 outside `docs/research`, 409 while recording or without a display); the icon is off while `short` is false and after a save (the save deleted the sibling) |
| My notes view | notes icon (`my notes`) in the toolbar of a game's report (not of a draft) | full-window panel over the report: per message part a card with `n/of` and two copy icons (`copy notes <n> files` = the captioned images, the big first icon; `copy notes <n> text`, smaller and muted after it; one paste carries files OR text, so two pastes). A marker with an empty note shows a note field (Enter saves through the note endpoint, then the list is re-read; Esc leaves the field), and the part's two copy icons and that marker's copy icon stay off until every marker of it has a note, then a row per marker: tag icon in the marker colour, `h:mm:ss`, the note kuhy typed, a thumbnail from `/api/sessions/<stamp>/still/<i>` (hourglass until cut: the list is re-read every 2 s, at most 60 times) and `copy marker <stamp> <i>`; session dates as `YYYY-MM-DD` rows; Esc or the close icon returns to the report; icons only |
| Copy icon | every copy control | copy glyph, spinner while the POST runs, check for 1.5 s on 200, error glyph (until the next tap) on 404/409/500 or no wrapper; off when there is nothing to copy |

## Core flows (3-5)

| id | goal | command | last green |
|---|---|---|---|
| F1 | GUI start, 4 hotkey + 4 button markers, stop by Mod+Shift+F4, full analysis with stub models | `e2e/run.sh F1 && e2e/run.sh F1-check` | 2026-11-12 (72 checks) |
| F2 | session stops by itself when the game exits | `e2e/run.sh F2` | 2026-11-11 |
| F3 | real Steam + Librarian off-screen: open, ring, Steam starts, game window, recording, CLI markers, game exit stops it | manual, CLAUDE.md "Driving the app" | 2026-11-11 (Xvfb :148) |
| F4 | the recording grabs the monitor the game window is on (DP-0 + HDMI-0 layout, game on HDMI-0 -> 2560x1440 video) | `E2E_LAYOUT=dual e2e/run.sh up`, `e2e/run.sh F4` | 2026-11-11 (Xvfb :147, monitors listed by `e2e/shim/xrandr`) |
| F5 | Discord share: finish the research, open the report, open my notes, tap the copy icons; each copy is pasted into a second non-headless Chromium on the Xvfb (`e2e/paste_page.html` writes `{files,names,text}` into its title, `e2e/check_paste.py` decodes it): files -> 8 captioned `0N_<tag>.jpg` (taller than the still), an empty note blocks the copy (409) until it is saved through the note endpoint, text -> starts with `**`, one marker -> 1 file, `copy short` on the draft -> <= 1900 chars, no `\|` | after F1 + F1-check: `e2e/run.sh F5` (4K screenshots: `SHOTS_DIR=<dir> e2e/run.sh F5-shots`) | 2026-11-12 (Xvfb :151, 4 pastes + empty-note case) |

F1-check asserts: 8 chapters at the marker offsets, each marker offset within
0.5 s of the moment the input was sent, the border flash visible in the
recording at each offset, frames / clips / contact sheet / stills, captions
from the second tier with haiku skipped, one captioned frame per frame stage 3 uses, the single draft filled with status lines (no `-pl`), the todo call and
8 ticks. On failure every flow prints `FAIL F<n> step <i>: <why>; shots:
<path>` and exits non-zero.
